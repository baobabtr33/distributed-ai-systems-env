# distributed-ai-systems-env

Terraform-provisioned GKE cluster with a scalable NVIDIA L4 GPU node pool and a Jupyter
environment, used to profile PyTorch DDP training and separate intra-node (PCIe) from
inter-node (network) NCCL collective cost.

**Status:** infrastructure code complete, never applied. No cluster has been created from
it and none of the Terraform below has been run against a real project.

## Layout

```
bootstrap/      gcloud script: GCS state bucket + API enablement (run once, by hand)
modules/
  gke-cluster/  VPC, subnet, Cloud NAT, private zonal cluster, CPU system pool
  gpu-nodepool/ L4 Spot pool; node_count and gpus_per_node are the experiment
  jupyter/      JupyterLab on the CPU pool, PVC, notebook mount, RBAC, artifacts bucket
  guardrails/   billing budget with forecast and actual-spend alerts
envs/dev/       root module and tfvars
notebooks/      chapter-3 DDP scripts and their generated notebooks
jobs/           indexed torchrun Job template
tools/          py_to_ipynb.py
```

## Getting started

```bash
PROJECT_ID=my-project make bootstrap        # state bucket, APIs
cd envs/dev && cp terraform.tfvars.example terraform.tfvars && $EDITOR terraform.tfvars
cd ../.. && make init BUCKET=my-project-tfstate
make up                                     # cluster + Jupyter, GPU pool at 0
make scale NODES=1 GPUS=2                   # intra-node config
make forward                                # then http://localhost:8888/lab
make jobs SCRIPT=train_ddp_cifar10.py NNODES=1 NPROC=2
make logs
make down
```

Prerequisites are in [docs/PLAN.md](docs/PLAN.md): a **paid** billing account (trial
accounts cannot hold GPU quota) and `PREEMPTIBLE_NVIDIA_L4_GPUS` >= 8 in your zone.
`make up` with quota at 0 creates the cluster and then fails on the node pool.

## The topology matrix

`node_count` and `gpus_per_node` default to 0 and 2, so an idle cluster costs only the
control plane. The same code produces the three measurement configs:

| Config | Machine type | Path exercised |
|---|---|---|
| 1 node x 2 GPU | `g2-standard-24` | Intra-node only (PCIe peer-to-peer) |
| 2 nodes x 1 GPU | `g2-standard-8` | Inter-node only (gVNIC / TCP) |
| 2 nodes x 2 GPU | `g2-standard-24` | Both paths within one job |

L4 has no NVLink, so intra-node transfers go over PCIe and the intra- versus inter-node
gap is narrower than it would be on A100/H100. `torch.profiler` does not label a NCCL
kernel as inter- or intra-node; that distinction comes from **differencing the configs
above at identical global batch size**, not from reading a single trace.

`COMPACT` placement is set whenever `node_count > 1`, so the inter-node number reflects
the interconnect rather than an arbitrary distance inside the zone.

## notebooks/

Vendored from [`book-examples/chapter3-distributed-training-with-pytorch-ddp`] on the
`sample/gke-gpu-jupyter` branch — the example code from *Distributed AI Systems* (Packt,
MIT), pinned at upstream commit `fd369f9`.

Both forms of every example are mounted, because they are not interchangeable:

- **`.py` is the entrypoint.** All 13 scripts read `RANK`, `LOCAL_RANK` and `WORLD_SIZE`
  from the environment and call `init_process_group`. Only `torchrun` sets those, so
  this is what the Job actually runs.
- **`.ipynb` is the same code to read and launch from.** Generated by
  `tools/py_to_ipynb.py`: a `torchrun` launch cell, then the source split at top-level
  definitions. **The source cells do not execute in a notebook kernel** — they raise
  `KeyError: 'RANK'` or hang in rendezvous. They are there to read and edit against.

Editing a notebook does not write back to its `.py`. Change the script and run
`make notebooks` to regenerate.

## How the mounts work

Two volumes, split by access pattern, because a GCE persistent disk is `ReadWriteOnce`
and Jupyter's node is not the GPU node:

| Path | Backing | Why |
|---|---|---|
| `/home/jovyan/work` (Jupyter) | PVC, `ReadWriteOnce` | Jupyter's atomic-rename checkpointing misbehaves on GCS FUSE |
| `/work` (Job pods) | `chapter3-scripts` ConfigMap, read-only | The Job needs the `.py` and nothing else |
| `/artifacts` (both) | GCS bucket via the FUSE CSI driver | Shared and multi-writer, so rank 0's trace outlives the pod |

The notebooks ship as ConfigMaps and an init container copies them onto the PVC with
`cp -n`, so a pod restart never clobbers an edit. Deleting the PVC reseeds from scratch.

## Cost and safety

- GPU pool defaults to **0 nodes**; `make down` scales it to 0 before destroying.
- Spot by default, roughly a third of on-demand, preemptible at 30 seconds' notice.
- The budget module alerts at 50% and 80% of actual spend and at 100% of *forecast*. A
  budget does not cap anything — the stop is `node_count = 0`.
- Nothing is exposed publicly: private nodes, `ClusterIP` only, access by
  `kubectl port-forward`. `authorized_cidrs` must list your own address — an empty list
  is rejected, because an empty `master_authorized_networks_config` denies *every*
  external address and locks `kubectl` out of the cluster it just built.
